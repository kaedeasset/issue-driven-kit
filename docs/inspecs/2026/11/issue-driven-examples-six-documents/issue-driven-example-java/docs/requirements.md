## 1. 背景・目的

Issue駆動の生成AI開発を、Java/Spring Bootによる**契約、利用実績、月次請求、入金、バッチ、監査**を含む企業向け業務システムへ適用し、データ整合性・例外系・再実行可能性・長期運用を意識した設計を検証する。

Node.js版（Web/API分離）や.NET版（Windowsネイティブ）と異なり、本サンプルは**JavaサーバーがHTML画面を生成する構成**を採る。新規開発での構成比較が目的であり、レガシーシステム移行ではない。

## 2. システム概要

- 仮称：ContractBilling Java。
- **クライアント**：ブラウザ（HTML、CSS、最小限のJavaScript）。PC向け。サーバーからHTMLを受信する。
- **サーバー**：Java 25 LTS + Spring Boot 4 + Spring MVC + Thymeleaf + Spring Security + Spring Data JPA。
- **DB**：PostgreSQL。スキーマ変更はFlyway等の明示的マイグレーション。
- **処理**：同期Web操作＋月次請求作成バッチ（管理画面起動/CLI起動が可能）。実行結果はDBに記録。
- **ユーザー**：管理者、契約担当、経理担当、閲覧担当。実在の契約/個人情報を扱わない。

## 4. MVP対象外

外部決済・口座振替、実在する税務制度への完全準拠、請求メール配信、複数税率・複数通貨、日割り計算、月途中の契約変更、企業別マルチテナント、外部ERP、PDF適格請求書、SaaS運用基盤、ユーザーセルフサービス、外部ID基盤連携。

## 5. 業務ルール

### 5.1 請求対象月・契約・料金

| ID | 規則 |
|---|---|
| JAVA-BR-01 | 対象期間は年月`YYYY-MM`。契約開始/終了・プラン適用も**月単位**とし日割りは行わない |
| JAVA-BR-02 | 契約開始月が対象月以前、終了月が未設定または対象月以後で、対象月に有効な契約を請求対象とする |
| JAVA-BR-03 | プラン変更は翌月以降に適用。対象月に適用する月額基本料金・従量単価はスナップショットを固定 |
| JAVA-BR-04 | 請求税抜＝基本料金＋利用数量×従量単価、税＝`floor(税抜×0.10)`、税込＝税抜＋税。円整数。10%は**サンプル固定モデル** |
| JAVA-BR-05 | 利用数量は0以上1,000,000以下。外部取込キー（契約内で一意）で重複実績を排除。対象月内の複数実績は合計 |
| JAVA-BR-06 | 請求は契約・対象月につき最大1件。バッチの再実行・並行起動でも重複請求しない |
| JAVA-BR-07 | ドラフト請求は差戻し/再計算を許容するが、確定済み請求は編集禁止。再計算の条件と監査を残す |
| JAVA-BR-08 | 入金は請求に対して複数回登録可能。ただし0円・負数は不可、累計入金が税込金額を超えない |
| JAVA-BR-09 | 入金参照番号は請求内で一意。再送で同じ入金が2度計上されない |
| JAVA-BR-10 | 状態遷移は規定の方向のみ。確定/入金の競合時はロックまたはバージョン検証で不整合を防ぐ |
| JAVA-BR-11 | デモ契約は有効月単位で登録。状態にPAUSED/CLOSEDを設ける場合、請求対象判定の意味を別途ADRで固定し、MVPは開始月/終了月による可否を正とする |

## 7. 受入条件

固定データ：顧客C001、契約S001、プランBASIC（月額1000円、従量150円/単位）、対象月2026-10、実績3単位。

| ID | シナリオ | 期待結果 |
|---|---|---|
| JAVA-AC-01 | S001の2026-10請求プレビュー | 税抜1450、税145、税込1595 |
| JAVA-AC-02 | 2026-10請求バッチ1回 | S001のドラフト請求が1件作成 |
| JAVA-AC-03 | 同バッチを再実行 | S001の請求件数は1件のまま、金額一致 |
| JAVA-AC-04 | 同じ月次バッチを2処理で並行実行 | 同契約・月の二重請求0件、ジョブ結果が追跡可能 |
| JAVA-AC-05 | 利用実績外部キーを重複登録 | 既存実績維持、二重計上なし |
| JAVA-AC-06 | 請求を確定後、プランを変更 | 確定請求の税込1595円は不変 |
| JAVA-AC-07 | 請求ドラフトを更新中に別担当が確定 | 不整合を出さず一方は競合/状態拒否 |
| JAVA-AC-08 | 1595円の請求に1000円入金 | 未収額595円、支払状態PARTIAL |
| JAVA-AC-09 | 残り595円入金 | 未収0円、支払状態PAID |
| JAVA-AC-10 | 同じ入金参照番号を再送 | 入金1件のまま、未収額不変 |
| JAVA-AC-11 | 残額を超える入金を登録 | 422相当の業務エラー、DB不変 |
| JAVA-AC-12 | viewerが請求確定HTTPリクエスト | 403、DB不変 |
| JAVA-AC-13 | 契約開始月が2026-11の契約を2026-10で実行 | 請求対象にならない |
| JAVA-AC-14 | 失敗注入した請求バッチを再実行 | 部分的な不正確定が残らず、再実行可能で履歴追跡可能 |
| JAVA-AC-15 | マイグレーション・seed・テストを2回実行 | 同じPASS、0件テストをPASS扱いしない |
| JAVA-AC-16 | 未認証/CSRFなしで書込要求 | 401またはログイン誘導/403、書込なし |

## 8. 非機能要件

| 分類 | MVP基準 |
|---|---|
| 整合性 | 請求作成・確定・入金はDBトランザクション、一意制約、競合制御、ロールバックで守る |
| 冪等性 | 同一契約/月のバッチ再実行、同じ入金キー再送の影響は1回分 |
| 性能 | 固定データ1万契約・各1実績の月次ドラフト生成を5分以内**目標**とし、環境と計測を公開 |
| 可観測性 | ジョブID、対象月、開始終了、処理数、失敗数、例外識別子、相関IDを保存 |
| セキュリティ | Spring Security、BCrypt等の適切なハッシュ、サーバー認可、CSRF対策、Cookie属性、機密非ログ化 |
| 保守性 | Maven Wrapper、Java25、単体/結合/バッチ試験、静的解析、DBマイグレーション |
| データ | 日時UTC/日本時刻表示、金額long整数、文字コードUTF-8、固定シードとサンプルデータ |
| 操作性 | PCブラウザ、フォームのラベル、検証エラー、二重送信防止、画面遷移の明確化 |
| 可用性 | MVPは単一サーバー構成。SLAは設けず、障害復旧手順を文書化 |

## 9. issue-driven-kit適用要件

現行の`issue-driven-kit`に**汎用Java editionは存在しない**。利用開始前に、本体の`shared/spec/issue-run-spec.md`を拠り所として、Java版の試験・確認コマンド・インストール・doctor・DryRunを設計・実装・受入試験する。

- `./mvnw verify` で単体・統合・必要なバッチ試験を実行し、テスト0件を誤って合格としない。
- Issueには目的、前提、合格の条件、再現可能な確認コマンド、失敗時の観点を記載する。
- 実装を指示するIssueと、**判定に使うテスト/仕様の変更を許可するIssueを分離**し、無人実行による判定基準の自己書換えを防止。
- ソースコード完成のみで「自動で正しく実装した」と結論せず、実行ログ、修正回数、失敗原因、人間の受入レビューを残す。
- 公開リポジトリに環境変数、DBパスワード、セッション秘密情報、本番顧客データを含めない。

## 10. リリース条件・優先度

- JAVA-F-01～14の機能を備え、JAVA-AC-01～16をテストで検証。
- 同月バッチの再実行/並行起動/中断・復旧を自動テストで証明。
- `./mvnw verify`、起動、ブラウザでの入力、月次請求→確定→入金がREADME通り再現可能。
- 管理者以外への過剰権限付与、請求二重作成、入金二重計上の重大欠陥が0件。
- 未検証の性能目標や運用制約を「合格」と断定せず注記する。

## 11. リスク・未決事項

- Java 25 / Spring Boot 4 /依存ライブラリ互換性は初期構築時に検証し固定する。
- バッチ実行の並列排他方式、請求の再計算方式、プランの有効期間の保存方式は基本設計に定義する。
- 本番業務に転用する際の税法、証憑保存、アクセス制御などは別途専門レビューが必要。
- 画面とバッチの競合、長時間処理、失敗時のコミット境界は結合テストで確認する。
