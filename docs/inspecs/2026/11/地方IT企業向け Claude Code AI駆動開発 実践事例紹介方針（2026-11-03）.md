# 地方IT企業向け Claude Code AI駆動開発 実践事例紹介方針

## 2026年11月3日｜説明会・企業訪問用の企画メモ

# 1\. 目的と基本方針

Claude CodeなどのAIコーディングエージェントを用いると、ソフトウェア開発の実装・テスト工程をどこまで短縮できるのか、実際の開発事例を使って技術者・経営者に説明する。単なる生成AIの一般論や導入コンサルティングではなく、第三者が確認できる成果物と記録を示すことを重視する。  
各企業の契約形態（SES、準委任、請負）、顧客案件での利用可否、導入方法、費用対効果については、その企業自身の判断に委ねる。説明者は各社に適用方式を押し付けない。

# 2\. 想定する対象者

地方の中小IT企業、受託開発会社、SES・請負を併営する会社の技術者・開発責任者。生成AIについて基本的な知識はあるものと想定し、ChatGPTの初歩的な説明に時間を使わない。コード補完や単発のコード生成と、リポジトリを対象にしたエージェント開発の違いを中心に扱う。

# 3\. 伝えるべき3つの内容

## (1) 従来の開発と何が違うか

従来：人間が仕様確認、コード実装、テスト作成、実行、原因調査、修正を主導する。AI活用：人間がIssueと完了条件を提示し、Claude Codeが既存コードを解析し、複数ファイルを変更し、テストを実行し、失敗時に修正を反復する。人間は要求内容、レビュー、承認を担う。AIがすべて正しく実施するという意味ではない。

## (2) 具体的な作業時間・テスト結果を見せる

記録する項目：開発対象とIssue番号／変更したファイル・行数／指示からテスト成功までの経過時間／人間が実際に作業した時間／テスト件数と成功・失敗／AIの再試行回数／レビュー修正／API利用費用（取得できれば）。  
比較対象の従来工数が実測できない場合は推定値だと明記する。「何倍速い」といった削減率は、同等条件の比較記録がない限り断定しない。実装時間だけでなく、テストとレビューまで含めた範囲を明示する。

## (3) 再現可能な実例を公開する

公開OSS：issue-driven-kit（https\://github.com/mkanakureon/issue-driven-kit）。適用例：rpg-online-cloudflare（https\://github.com/mkanakureon/rpg-online-cloudflare）。公開可能な範囲でIssue、設計書、Pull Request、コミット、CI・テストログ、実際の作業手順を示す。適用例リポジトリやログの公開状況は説明前に確認する。

# 4\. 30〜40分の説明会構成

0〜5分：Claude Codeとコード補完・チャット型生成AIとの違い。  
5〜15分：実際のGitHub Issueを起点として、解析→実装→テスト→修正→レビューまでの一連の流れを紹介。  
15〜25分：計測した開発時間、AI実行ログ、テスト結果、人間が介入した箇所、失敗例を示す。  
25〜30分：公開OSS・サンプル環境・再現手順を案内。  
30〜40分：質疑応答。顧客契約や導入可否は各社判断と明示する。

# 5\. 事例資料の準備

事例は機能の規模が異なるものを1〜3件用意する。各事例を「目的／Issue／入力指示／生成・変更内容／テスト／所要時間／人間のレビュー／結果・制約」の同じ形式で示す。成功例だけでなく、AIが誤った実装をした例や修正に時間を要した例も含める。可能ならデモ用に固定コミットと手順を用意し、再現可能性を確認する。

# 6\. 伝えない・断定しないこと

「AIを導入しない企業は生き残れない」という主張をしない。実測のない工数削減率を示さない。AIが人間のレビューや品質保証を不要にするとは説明しない。各社のセキュリティ・契約条件を知らずに導入可能と断定しない。Claude Codeの実行が成功したことと、納品品質が保証されたことを区別する。

# 7\. 企業に判断してもらう事項

実案件に適用するか、顧客と何を合意するか、利用を許可する情報の範囲、利用コスト、レビュー責任、品質保証、契約形態、社員教育、社内標準化については各社が決める。説明者が提案するのはツールの利用契約ではなく、実例と検証可能な手順である。

# 8\. 対外説明用の紹介文

Claude Codeを活用したAI駆動開発の実践事例紹介  
Claude CodeなどのAIコーディングエージェントにより、ソフトウェア開発の実装・テスト工程がどこまで効率化できるのか、実際の開発事例を通じて紹介します。GitHubのIssueを起点に、AIがコードの実装、テストの実行、不具合の修正を進める過程を、成果物と実行記録で説明します。開発手順はOSSとして公開し、興味のある方が検証できるようにします。各企業の業務や顧客案件への適用は、それぞれの事情に応じてご判断いただくことを想定しています。

# 9\. 準備完了の確認

□ 公開可能な事例1〜3件がある　□ Issueとコミットを提示できる　□ テスト成功の証拠がある　□ 計測範囲と計測方法が明記されている　□ 人手のレビュー時間を含めている　□ 失敗例・適用限界を説明できる　□ OSSや再現手順へアクセスできる
