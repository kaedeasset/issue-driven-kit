# コミットの決まり

**これ 1 か所が正。** フック（`hooks/commit-msg`・`hooks/pre-commit`）はこの文書のとおりに検査する。取り込んだ repo のスキルや `CLAUDE.md` には中身を写さず、この文書を指す。

## メッセージの形

```
fix(login): 期限切れのときにログイン画面へ戻す

期限が切れても前の画面に留まり、操作がすべて失敗していた。
期限切れを受けたらログイン画面へ戻す。

確かめ: 単体テスト 42 件 PASS。期限を 1 秒にして手で戻ることを確認。

---
原因は思ったより手前にあった。

Co-Authored-By: Claude {モデル名} <noreply@anthropic.com>
```

| 部分 | 決まり |
|---|---|
| 件名 | `種類(範囲): 説明`。種類は `feat`（新機能）・`fix`（不具合）・`docs`（文書だけ）・`refactor`（動作を変えない整理）・`chore`（ビルド・設定・スクリプトの手入れ）・`test`（試験だけ）。範囲は省ける。**説明は 40 字以内**で、何をしたかだけ書く。指示の引用・細目・日付・ハッシュは本文へ |
| 空行 | 件名の次は空行 |
| なぜ・変えたこと | 本文の頭。1 行以上。細目は `- ` の箇条書き |
| 確かめ | `確かめ:` で始まる行を 1 行。何を回して何が出たか。回していなければ `確かめ: なし（文書のみ）` のように**回していないと書く** |
| 感想 | `---` だけの行の後に 1〜3 行。作業を振り返った正直な感想を、ゆるいトーンで（「地味だけど大事」「ここで詰まった」など） |
| 末尾 | AI が書いたときは `Co-Authored-By: …`（感想の後。フックは検査しない） |

## 検査（commit-msg）

| # | 検査 | 内容 |
|---|---|---|
| M1 | 件名の形 | `種類(範囲): 説明`。種類は上の 6 つ（repo で足せる。下の「値の 3 段」） |
| M2 | 説明の長さ | `: ` より後が **40 字以内**（バイト数でなく文字数） |
| M3 | 空行 | 件名の次の行が空行 |
| M4 | 本文と確かめ | `確かめ:`（全角の `：` も可）の行があり、それ以外の本文も 1 行以上ある |
| M5 | 感想 | `---` だけの行があり、その後に `Co-Authored-By:` 以外の行が 1 行以上ある |

検査しない件名: `Merge ` で始まるもの・`Revert "`・`fixup!`・`squash!`・`amend!`。`#` の行（git のコメント）は数えない。

## 検査（pre-commit）

| # | 検査 | 内容 |
|---|---|---|
| P1 | 無理に足したもの | 今回**足す**ファイルのうち `.gitignore` に当たるもの（`git add -f`）を止める。載せない物の一覧は `.gitignore` だけで管理する |
| P2 | 秘密 | `.env`・`.env.*`・`credentials.*`・`*.pem`・`*.key`・`.claude/settings.local.json` を足す・変えると止める |
| P3 | 大きさ | 1 ファイルが 95MiB を超えたら止める（GitHub は 100MiB で push を拒む）。50MiB を超えたら警告だけ |
| P4 | 生成物 | フレームワークが作るフォルダ（`generated=`。Unreal の `Binaries/`・Unity の `Library/`・Node.js の `node_modules/` など）と、OS が作るファイル（`generated_os=`。`.DS_Store`・`._*`・`Thumbs.db`・`desktop.ini`）を足す・変えると止める。`.gitignore` が漏れていても止まる |
| P5 | Unity の `.meta` | `meta_pair=yes`（Unity）のとき。`Assets/` の下に足したファイルとその上のフォルダに `.meta` が無い・`.meta` だけを足す・アセットを消して `.meta` が残る、を止める |
| P6 | マップの載せ漏れ（警告） | `ofpa_check=yes`（Unreal）のとき。1 アクタ 1 ファイルのマップ（`.umap` と `__ExternalActors__/<マップ>/`・`__ExternalObjects__/<マップ>/`）の一部だけをステージすると、残っている本数と先頭 3 本を警告する。コミットは止めない |
| P7 | LFS の素通り | `lfs_check=yes`（既定）のとき。`.gitattributes` で `filter=lfs` の対象なのに、中身が 1KiB を超える（ポインタでない）ものを止める。`git lfs install` をしていない PC で起きる |

## 値の 3 段

種類の一覧・字数・大きさ・生成物などの値は、上の段ほど優先して読む。

| 段 | ファイル | 直す場所 |
|---|---|---|
| 1 | 取り込んだ repo の直下の `commit-hooks.conf`（`profile=` と、その repo だけの違い） | その repo。commit-hooks の更新では上書きされない |
| 2 | `profiles/<profile>/profile.conf`（`unreal`・`unity`・`node`・`plain`） | このリポジトリ |
| 3 | `profiles/common.conf`（全部の名前と既定） | このリポジトリ |

上の表の数（40 字・95MiB など）は 3 段目の既定。フレームワーク別のステージの決まりは `profiles/<profile>/stage.md`。

## 止まったら

**`--no-verify` を使わない。** 表示された項目どおりにメッセージか中身を直して、コミットし直す。メッセージは `git commit -F <ファイル>` で渡す（PowerShell の here-string を `-m` に置かない）。
